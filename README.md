# 城会玩 2.0

> 城市照片手账 · 旅行回忆归档 · 城市足迹点亮 · 好友共享旅行地图

一款围绕城市照片手账、旅行回忆归档、城市足迹点亮和好友共享设计的微信小程序。用户可以在中国地图上点亮去过的城市，把旅行照片、美食照片和文字笔记绑定到具体城市；之后想找某次旅行的美景或美食时，直接进入城市页即可回看，不需要在系统相册里反复翻找。

## 项目定位

城会玩 2.0 想解决的是旅行记录分散、照片和地点脱节、旅行结束后回忆难以检索的问题。很多时候我们拍了大量美景和美食照片，但真正想找"那次在某座城市吃过什么、拍过什么"时，只能在系统相册里来回翻。这个项目把"城市"设计成照片和笔记的容器，让每张照片从上传开始就带着地点上下文：

**核心价值：照片不再只按时间存在，而是按城市被找回。** 用户点进一座城市，就能看到自己在那里上传过的美景、美食和文字记录。

- **地图是入口**：在中国地图上查看 34 个省级行政区和 391 座城市，点亮已经探索过的地方。
- **城市是相册**：每座城市都可以保存旅行照片、美食照片和文字笔记，形成独立的城市记忆页。
- **相册是检索入口**：照片支持按全部、旅行、美食和城市筛选，适合旅行后快速找回某座城市的内容。
- **角色卡是奖励**：首次点亮省份时触发地域角色卡和成就反馈，让记录过程更有仪式感。
- **群组是共享视角**：加入群组后，成员之间的点亮城市、城市照片和相册动态会合并展示，让朋友、情侣或家人拥有一张共同旅行地图。

## 功能总览

### 地图探索

- 支持 34 个省级行政区、391 座城市的旅行足迹管理。
- 已点亮省份会在地图和省份标签中同步展示进度。
- 城市搜索：输入城市名实时筛选，搜索结果标记已打卡城市，点击直达城市详情。
- 下一站推荐：从城市攻略库中随机推荐未打卡城市，支持换一个重新推荐。
- 城市详情页展示省份主题图、必打卡地标、旅行攻略、避坑指南、点亮状态、旅行照片、美食照片和旅行笔记。
- 本地记录与云端记录结合，未加入群组时也能保存自己的旅行数据。
- 支持取消打卡和移除城市记录，操作前有确认提示防止误触。

### 旅行照片上传与城市相册

- 城市详情页可上传旅行照片和美食照片，照片会归属到对应城市。
- 上传时记录城市、省份、照片类型、时间、图片地址和文字说明，避免照片脱离地点语境。
- 上传页城市选择器支持搜索筛选，热门城市快捷选择，搜索结果标记已打卡城市。
- 相册页按全部、旅行、美食进行筛选，并按城市聚合查看。
- 相册支持长按照片删除，删除时同步清除本地和云端记录。
- 相册空状态引导用户前往地图选择城市，形成自然的使用路径。
- 动态页会显示"点亮城市""上传旅行照片""记录美食"等真实行为。
- 已加入群组时，成员上传到同一城市的照片会在城市详情、相册和动态中同步可见。

### 角色卡与成就反馈

- 角色卡不是主线功能，而是围绕"记录城市"设计的奖励反馈。
- 点亮省份后解锁对应地域角色卡。
- 支持 N / R / SR / SSR / UR 五级稀有度。
- 卡片详情展示角色插画、地域文案、稀有度和收集状态。
- 抽卡页加入翻牌和光效反馈，让解锁过程更有仪式感。

### 成就系统

- 覆盖探索、收集、照片、社交、特殊时间等多个维度，共 30+ 成就徽章。
- 打卡成功、解锁卡片、上传照片时会触发对应成就提示。
- 成就墙展示徽章、进度、分类和完成状态，方便用户继续探索。
- 特殊成就包括夜猫子（凌晨打卡）、早鸟（清晨出发）、闪电侠（单日多城）等隐藏成就。

### 群组共享

- 群组作为底部导航独立 Tab，突显共享旅行视角的产品特色。
- 支持创建群组并生成 6 位邀请码，好友输入邀请码即可加入。
- 群组类型分为朋友、情侣、家人三种。
- 群组不是单独的上传空间，而是一种共享旅行视角。
- 成员点亮的城市会合并到群组地图；成员在城市里上传的照片会出现在对应城市详情、相册和动态中。
- 群组页展示共享城市、最近足迹照片、成员排行和邀请入口。
- 支持退出群组，退出后不再同步该群组数据。

### 我的页面

- 展示头像、昵称、探索经验、点亮城市、探索省份、照片数量和探索进度。
- 支持编辑昵称、头像，查看相册、成就和设置。
- 最近动态会按省份和城市展示真实记录，减少无意义占位内容。
- 支持清除所有旅行数据（本地 + 云端同步清除）。

### 数据管理

- **取消打卡**：在城市详情页点击"已打卡"可取消，弹出确认提示，同步删除云端记录。
- **移除城市记录**：一键清除某城市的打卡状态、所有照片、笔记和访问日期。
- **删除照片**：城市详情页和相册页均支持删除照片，同步清除云端记录。
- **删除笔记**：笔记标题右侧提供删除按钮，同步清除云端笔记。
- **清除全部数据**：设置页和个人页均提供入口，同时清除本地缓存和云端数据。
- **数据同步**：采用替换模式，以云端为准，防止删除操作后数据被恢复。

## 核心体验路径

```
打开中国地图 → 点亮去过的城市 → 进入城市详情页
    → 上传旅行/美食照片 → 写旅行笔记
    → 相册按城市/类型筛选回看
    → 首次点亮省份 → 解锁地域角色卡
    → 触发成就徽章反馈
    → 创建/加入群组 → 成员城市和照片同步展示
    → 形成完整的旅行记忆闭环
```

## 能力架构

| 模块 | 说明 |
| --- | --- |
| 地图与城市索引层 | 用省份、城市、地标和经纬度组织旅行足迹；城市既是地图点位，也是照片、笔记和动态的索引入口 |
| 照片上传与归档层 | 旅行照片、美食照片和文字笔记绑定到具体城市，形成可按地点检索的城市记忆 |
| 角色卡与成就激励层 | 点亮省份、上传照片、收集卡片都会获得反馈，但它服务于记录主线，不替代照片归档 |
| 群组共享同步层 | 通过邀请码建立旅行小队，合并成员的点亮城市、城市照片和动态 |
| 内容安全层 | 上传内容接入微信内容安全能力，兼顾用户记录体验和小程序合规 |
| 数据管理层 | 支持取消打卡、删除照片、删除笔记、清除全部数据，所有删除操作同步本地和云端 |

## 云函数说明

### login

获取用户 openid，初始化基础身份信息。写入 `users` 集合，记录昵称、头像、登录时间等。

### syncData

个人数据同步核心，支持以下操作：

| Action | 功能 |
| --- | --- |
| `syncCityRecords` | 批量同步城市打卡记录 |
| `syncPhotos` | 批量同步照片 |
| `syncNotes` | 同步笔记 |
| `syncAvoidTips` | 同步避坑指南 |
| `getAllData` | 拉取用户全部云端数据 |
| `clearAllData` | 清除用户所有云端数据 |
| `removeCityRecord` | 删除单个城市记录（含照片和笔记） |
| `removePhoto` | 删除单张照片 |
| `removeNote` | 删除单条笔记 |
| `removeAvoidTip` | 删除单条避坑指南 |

### group

群组管理核心，支持以下操作：

| Action | 功能 |
| --- | --- |
| `getMyGroup` | 获取当前用户所在群组详情 |
| `createGroup` | 创建群组并生成邀请码 |
| `joinGroup` | 通过邀请码加入群组 |
| `leaveGroup` | 退出群组 |
| `syncMemberStats` | 同步成员统计数据 |
| `syncCityRecord` | 同步城市打卡记录到群组 |
| `sharePhoto` | 分享照片到群组 |
| `getCityFootprint` | 获取群组内某城市的访问足迹 |
| `getSharedPhotos` | 获取群组共享照片 |

### contentSecurity

调用微信内容安全 API，保障上传内容合规。

| Action | 功能 |
| --- | --- |
| `checkText` | 文字内容安全检测 |
| `checkImage` | 图片内容安全检测 |

### getAssetUrl

将云存储文件 ID 转换为可展示的临时 URL。

### listCloudFiles

批量获取云存储文件链接，辅助管理云存储资源。

## 云数据库集合

| 集合名 | 用途 | 主要字段 |
| --- | --- | --- |
| `users` | 用户信息 | openid, nickName, avatarUrl, stats, privacy, groups |
| `cityRecords` | 个人城市打卡记录 | openid, cityId, provinceId, isVisited, visitTime |
| `photos` | 个人照片记录 | openid, cityId, provinceId, type, fileId, url |
| `notes` | 个人旅行笔记 | openid, cityId, provinceId, content |
| `avoidTips` | 个人避坑指南 | openid, cityId, provinceId, content |
| `groups` | 群组信息 | name, type, inviteCode, creatorOpenid |
| `group_members` | 群组成员 | groupId, openid, nickName, role, cityCount, cityIds |
| `group_city_records` | 群组城市打卡记录 | groupId, openid, cityId, cityName, provinceId |
| `group_photos` | 群组共享照片 | groupId, openid, fileId, cityId, type |

> 部署时需要在云开发控制台手动创建以上集合，并设置合适的权限规则（建议仅创建者可读写）。

## 本地运行

### 前置要求

- [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（最新稳定版）
- 微信小程序账号（已在[微信公众平台](https://mp.weixin.qq.com)注册）
- 已开通微信云开发环境

### 步骤

```bash
git clone https://github.com/tl66666/chw2.0.git
```

1. 打开微信开发者工具，导入 `城会玩2.0/` 目录。
2. 填写你的小程序 AppID。
3. 开通微信云开发环境（工具栏 → 云开发 → 开通）。
4. 在云开发控制台创建以下数据库集合：
   - `users`、`cityRecords`、`photos`、`notes`、`avoidTips`
   - `groups`、`group_members`、`group_city_records`、`group_photos`
5. 右键 `cloudfunctions/` 下每个云函数文件夹 → "上传并部署：云端安装依赖"。
6. 编译运行小程序，进入首页后即可体验完整功能。

## 数据管理说明

城会玩 2.0 的数据管理遵循"用户可控、删除彻底"原则：

| 操作 | 入口 | 影响范围 |
| --- | --- | --- |
| 取消打卡 | 城市详情页 → 已打卡按钮 | 移除打卡状态 + 云端 cityRecords |
| 移除城市记录 | 城市详情页 → 移除记录按钮 | 清除该城市所有数据（打卡+照片+笔记+日期）+ 云端三表 |
| 删除照片 | 城市详情页 × / 相册长按 | 移除本地照片 + 云端 photos 记录 |
| 删除笔记 | 城市详情页 → 删除按钮 | 清空本地笔记 + 云端 notes 记录 |
| 删除避坑指南 | 城市详情页 → 删除按钮 | 清空本地避坑指南 + 云端 avoidTips 记录 |
| 清除全部数据 | 设置页 / 个人页 | 清除本地所有旅行数据 + 云端所有个人数据 |

所有删除操作均带确认提示，防止误触。云端同步采用替换模式，确保删除后重新进入小程序不会恢复已删除的数据。

## 设计思路与实现重点

- **痛点拆解**：系统相册按时间排列，适合浏览最近照片，但不适合回到"某座城市"的旅行场景。城会玩 2.0 将城市详情页作为上传入口，让照片在产生时就带上城市上下文。
- **数据组织**：照片记录保留城市、省份、类型、时间、图片地址、文字描述等字段；相册页再基于这些字段做聚合和筛选，避免照片只成为无序图片列表。
- **核心流程**：选择城市 → 上传旅行/美食照片 → 写入城市照片记录 → 城市详情页展示 → 相册按城市/类型筛选 → 动态和群组同步。
- **体验闭环**：点亮城市 → 上传照片 → 形成城市记忆页 → 按城市回看 → 角色卡/成就反馈 → 群组共享同一份旅行视角。
- **工程取舍**：地图、相册、群组和成就都围绕"城市记忆"服务；角色卡不是主线功能，而是提升持续记录意愿的反馈层。
- **难点处理**：上传图片需要同时考虑体验和合规，因此项目在上传前后加入状态提示、失败兜底、内容安全校验和本地缓存，避免用户记录中断。
- **数据一致性**：删除操作同时清除本地缓存和云端记录，云同步采用替换模式而非合并模式，从根本上避免"删了又恢复"的问题。

## 体验亮点

- **完整闭环**：点亮城市、上传照片、按城市回看、解锁角色卡、同步群组，形成持续反馈。
- **共享逻辑清晰**：群组共享的是地图和城市记录，不是孤立的聊天室或照片墙。
- **记录颗粒度细**：照片和笔记绑定到具体城市，后续浏览时不会失去地点上下文。
- **视觉风格统一**：粉色、奶油白和城市插画构成柔和旅行感，避免工具化界面。
- **产品完成度高**：首页进入、地图点亮、城市详情、相册、角色卡、成就、群组和我的页面形成完整链路。
- **数据可控**：所有用户数据均可编辑、删除，删除操作同步清除本地和云端，用户对数据有完全控制权。
