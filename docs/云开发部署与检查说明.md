# 云开发部署与检查说明

## 本次不需要新增或删除的资源

请保留现有数据库集合：

- `avoidTips`
- `cityRecords`
- `group_city_records`
- `group_members`
- `group_photos`
- `groups`
- `notes`
- `photos`
- `users`

请保留现有云存储目录：

- `avatars`
- `cards`
- `cities`
- `city-checkins`

不要在云开发控制台中批量删除集合、集合字段或这些目录。程序会在用户确认删除某张相册照片时，自动清理该照片对应的 `photos` 记录和云存储文件；手动批量删除会造成数据库记录和图片文件不一致。

## 需要重新部署的云函数

本次只需重新部署 `group` 云函数。`syncData` 已经包含删除个人照片记录的 `removePhoto` 动作，不需要新增集合或云函数。

部署步骤：

1. 在微信开发者工具左侧打开“云开发”。
2. 选择“云函数”，找到 `group`。
3. 在项目资源管理器中右键 `cloudfunctions/group`，选择“上传并部署：云端安装依赖”。
4. 等待工具提示上传完成，再到云开发控制台的“云函数”列表点击刷新。
5. 确认 `group` 的“最后更新时间”已更新，状态仍为“已部署”。

不要删除控制台中的 `group` 函数后再新建，也不要只上传 `index.js` 文件。必须上传整个 `cloudfunctions/group` 文件夹，新增的 `permissions.js` 才会同时部署。

## 数据库权限建议

小程序的读写都通过云函数完成，因此上述集合不要设为“所有用户可读写”。在“数据库 -> 数据库权限”中，为这些业务集合选择“仅创建者可读写”或保持当前的严格权限；云函数使用服务端权限执行群组汇总、转让和删除操作。

如果以前为了调试将集合设为“所有用户可读写”，建议恢复严格权限，尤其是 `groups`、`group_members`、`group_photos` 与 `photos`。

## 部署后检查

1. 重新编译小程序并登录测试账号。
2. 在相册中长按一张自己的照片，确认删除后返回相册，照片和统计数字应立即减少。
3. 关闭并重新打开小程序，已删除照片不应重新出现。
4. 若测试账号在群组中，打开群组照片墙，已删除照片不应再显示。
5. 用两个测试账号创建群组。群主点击退出时应先出现“转让给某成员”的选择；普通成员可直接退出。

## 发生异常时

- 如果删除后照片重新出现：先确认 `syncData`、`group` 都显示“已部署”，然后在云开发控制台检查 `photos` 与 `group_photos` 中是否仍有该文件 ID 的记录。
- 如果群组创建、加入或转让失败：打开 `group` 的“日志”，查看同一时间的错误信息；不要先删除数据库记录。
- 如果云存储中的图片没有删除，但相册已经不显示：不影响用户数据展示。下一次打开相册时程序会重试云端清理；仍然失败再根据日志处理。
