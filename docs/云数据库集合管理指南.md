# 云数据库集合管理指南

这份说明对应“城会玩 2.0”当前代码。先给结论：**保留原有 9 个集合，仅新建 3 个空集合；不要删除集合，不要手工删字段或批量删数据。**

当前小程序不使用 `wx.cloud.database()` 直接访问数据库，所有数据由云函数处理。因此下面 12 个集合都应在云开发控制台设为 **“所有用户不可读写”**。这不会影响小程序：云函数和控制台仍拥有服务端权限；它只阻止普通用户绕过页面直接修改数据库。

我已重新核对代码，数据库 SDK 只出现在 `login`、`syncData`、`group` 三个云函数中。腾讯云开发官方的[基础权限说明](https://docs.cloudbase.net/database/data-permission)也将“无权限”列为“需要服务端处理的敏感数据”的适用场景，所以这里不是沿用默认值，而是与当前架构匹配的明确设置。

## 在控制台设置权限

1. 打开微信开发者工具，确认当前项目已经选择正确的云开发环境。
2. 点击顶部“云开发”，进入“数据库”。
3. 逐个点击下表中的集合名称，打开“权限设置”或“数据库权限”。
4. 选择预设规则里的 **“所有用户不可读写”** 并保存。
5. 对 12 个集合全部重复一次。不要自己填写自定义安全规则，除非以后新增了小程序端直连数据库的代码。

## 现有集合说明

| 集合 | 是否保留 | 用途 | 常见字段 | 手工操作建议 |
| --- | --- | --- | --- | --- |
| `users` | 保留 | 用户资料、个人统计与登录关联 | `_openid`、`nickName`、`avatarUrl`、`stats` | 不删除，不要手改 `stats` 或群组关联字段。 |
| `cityRecords` | 保留 | 个人点亮城市记录 | `_openid`、`cityId`、`provinceId`、`isVisited` | 删除城市时由程序处理，不批量删除。 |
| `photos` | 保留 | 个人相册照片索引 | `_openid`、`cityId`、`fileId`、`type` | 相册长按删除会处理对应记录；不要手工按 URL 清理。 |
| `notes` | 保留 | 个人旅行笔记 | `_openid`、`cityId`、`content` | 只通过小程序编辑或删除。 |
| `avoidTips` | 保留 | 个人避坑提示 | `_openid`、`cityId`、`content` | 只通过小程序编辑或删除。 |
| `groups` | 保留 | 群组基本信息 | `name`、`type`、`inviteCode`、`creatorOpenid` | 不直接改邀请码、群主或成员数量。 |
| `group_members` | 保留 | 群成员与成员贡献统计 | `groupId`、`openid`、`role`、`cityCount`、`photoCount` | 退出和转让群主由程序处理；不要手动删除成员。 |
| `group_city_records` | 保留 | 群成员加入群后产生的城市足迹 | `groupId`、`openid`、`cityId`、`provinceId` | 新建/加入群组默认从 0 开始，之后的打卡才写入这里。 |
| `group_photos` | 保留 | 群内共享照片索引 | `groupId`、`openid`、`fileId`、`cityId` | 只有照片上传者可删除自己的群照片。 |
| `group_photo_comments` | 新增 | 群照片留言 | `groupId`、`photoId`、`openid`、`content` | 留言者可删除自己的留言，群主可管理全群留言。 |
| `group_trip_plans` | 新增 | 群组旅行计划与目的地愿望清单 | `groupId`、`title`、`cityName`、`startDate`、`endDate`、`creatorOpenid` | 由计划创建者或群主删除，不手工改计划归属。 |
| `group_plan_votes` | 新增 | 成员对旅行计划的投票记录 | `groupId`、`planId`、`openid` | 一条记录代表一票；不要手工增加或删除。 |

## 本轮只需要新建三个集合

原来的 9 个集合一个都不要删除、重建或清空。本轮仅在“数据库 -> 集合管理”中点击“新建集合”，依次输入以下三个名字并确认创建：

1. `group_trip_plans`
2. `group_plan_votes`
3. `group_photo_comments`

创建空集合即可，**不要先手工添加字段、记录或安全规则代码**。部署新版 `group` 云函数后，第一次创建旅行计划、投票或照片留言时，程序会自动写入字段。随后把这三个新集合和原来的 9 个集合一样，设置为“所有用户不可读写”。

## 云存储目录

以下目录也应保留：`avatars`、`cards`、`cities`、`city-checkins`。

数据库记录与云存储文件相互关联。手动从云存储批量删除文件，或只从数据库删除照片记录，都会留下不一致的数据。相册中不需要的照片请在小程序里长按删除。

## 本轮必须部署的云函数

需要部署两个函数：`group` 与 `syncData`。

1. 在开发者工具左侧“资源管理器”找到 `cloudfunctions/group`。
2. 右键它，选择“上传并部署：云端安装依赖”。
3. 等待成功提示后，对 `cloudfunctions/syncData` 重复同样操作。
4. 在云开发控制台“云函数”列表刷新，确认两者的更新时间变为刚刚部署的时间。
5. 重新编译小程序，再测试相册删除、创建群组、加入群组与退出群组。

本轮需要新建 `group_trip_plans`、`group_plan_votes` 与 `group_photo_comments` 三个空集合，不需要迁移旧数据。旧群组保留原来的共同足迹；以后新建或新加入的群组会从 0 开始累计，不会把个人历史自动带进去。

## 关于认证与邀请码

你当前是个人非商业项目，并且小程序已完成备案、审核和线上发布，**不需要为了群组功能强行做微信认证**。群组继续使用“复制邀请码 -> 对方在群组页输入邀请码加入”的流程，不依赖分享卡片或营业执照。

后续如果要做公开传播、付费服务、企业主体功能，或接入需要主体资质的微信能力，再评估认证即可。现阶段认证不会解决数据安全或邀请码加入的问题。
